# AI Analysis Flow

The `ai_api/analysis/` directory contains the **Intelligence Layer** of AcuteSim.
Unlike `compute/`, which focuses on raw number crunching, this module focuses on **Semantic Understanding**. It translates low-level simulation artifacts (Statistics, Netlists) into high-level concepts (Failure Modes, Topologies) that LLMs and humans can understand.

## Core Responsibilities

1.  **Failure Classification**: Converting "Node 5: KCL Residual 1e-3" into "Floating Node at Base of Q1".
2.  **Topology Recognition**: Converting "R1, R2, Q1" into "Common Emitter Amplifier with Voltage Divider Bias".
3.  **Prompt Engineering**: Generating token-efficient summaries of the circuit state for the AI Assistant.

## Key Files

### 1. `failure_taxonomy.h`: The Error Vocabulary
Defines a structured enum of all possible simulation failures (`FailureType`).
*   **Purpose**: Provides a stable, machine-readable contract for error reporting.
*   **Features**:
    *   `FailureLabel`: Combines Type, Severity, and Context (e.g., "Critical: Singular Jacobian at Node 5").
    *   `toJson()`: Serializes errors for RAG (Retrieval-Augmented Generation) indexing.

### 2. `topology_analyzer.h`: The Circuit Vision
Implements structural pattern matching to identify analog building blocks.
*   **Functional Blocks**: Recognizes `COMMON_EMITTER`, `DIFFERENTIAL_PAIR`, `CURRENT_MIRROR`, etc.
*   **Signal Paths**: Traces the flow from Source -> Amplifier -> Load.
*   **Prompt Compression**: Generates shorthand descriptions (e.g., "Stage1: CE(Q1, Av=-40)") to save LLM context window space.

### 3. `drc_engine.h` (Concept)
Validates Design Rules against the `dr_validity` masks generated by the `compute/tensors` layer (e.g., Thermal Runaway checks).

## Data Flow

1.  **Simulation Ends**: The `compute/` engine returns a `SolverResult` with raw statistics.
2.  **Failure Labeling**: `FailureLabeler::labelFailures` scans the stats. If `residual > 1.0`, it checks for floating nodes or loops.
3.  **Topology Analysis**: `TopologyAnalyzer::identifyFunctionalBlocks` scans the netlist to provide context (e.g., "The failure happened in the Bias Network").
4.  **AI Context**: The combined report (Failure + Topology) is sent to the AI Assistant or the "Debug Doctor" UI.

## Development Rules

1.  **No Physics Here**: This layer analyzes *results*, it does not run *simulations*. It depends on `components/` and `compute/` (for types), but never the reverse.
2.  **LLM-Friendly Output**: All string outputs should be optimized for clarity and brevity to serve as effective prompts.
3.  **Heuristic Flexibility**: Unlike the physics engine, this layer deals with "fuzzy" concepts. It's acceptable to have "Unknown" blocks or strictly heuristic classifications.
